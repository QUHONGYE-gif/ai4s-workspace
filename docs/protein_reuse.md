整理：陈铠洲；更新：2026-10-22。状态：供陈铠洲与曲鸿烨共同讨论的草稿，尚未经过双方确认。本文直接写明 R001–R004 中与复用、缓存、加速有关的实际观察和限制，队友无需先打开四份原始记录；完整实验过程、环境、命令、文件与归档已整合进第一份 [流程与实验说明](protein_pipeline.md)。依据为真实产物及固定版本源码；没有进行缓存开/关计时对照，没有测得加速比。文档与代码位于个人开发分支 [`dev-ckz`](https://github.com/QUHONGYE-gif/ai4s-workspace/tree/dev-ckz)，尚未获准合入 `main`。文末及表内的原始记录/源码链接仅供进一步核查。

## 1. 当前结论与证据范围

已验证的是流程能生成并连接产物，以及工具中存在部分缓存/跳过机制。R003 日志显示 `Using cached IGSO3.`；R002 已建的 Swiss-Prot 库在 R003 被再次使用。当前控制脚本始终要求新输出目录，**尚未实现跨运行的科学结果缓存或自动复用策略**。

R004 还实际复用了 R003b 的设计 FASTA，从搜索步骤继续运行，说明上游结果可以作为后续分支输入；这次没有重跑骨架与序列生成，也没有测量自动复用策略的收益。CPU/GPU 使用相同查询和源 FASTA，但阳性命中集合及筛选 A3M 不同，不能仅凭查询相同就将两个后端的搜索结果视为等价缓存。具体观察和协作含义直接列在下文。

本文中的“已核实”指运行或固定版本源码提供依据；“建议／候选”是 Codex 整理的讨论方案；第 5 节为待双方确认内容，未形成共同决定。

源码行为、实际使用和性能收益需分别判断：发现缓存分支不等于证明命中正确；观察到缓存命中也不等于测出了加速比。以下提出复用条件和评测候选，供团队选择下一步，不能作为已验证研究收益引用。

### 1.2 CPU/GPU 差异为什么影响复用身份

R003 与 R004 的严格搜索都设置 E≤0.001、最低一致性 0.3、查询覆盖 0.8、候选上限 500、10 线程，保留比对并精确计算一致性；CPU 灵敏度为 `-s 7`，GPU 使用 `--gpu 1` 且不传 `-s`，采用最高灵敏度。两条设计查询均无命中；天然 P69905 的观察如下：

| 观察项 | CPU R003 | GPU R004 |
| --- | --- | --- |
| 命中目标数 | 498 | 498 |
| 目标集合关系 | 487 个共同目标，11 个 CPU 独有 | 同一批共同目标，另 11 个 GPU 独有 |
| 原始 A3M 记录数 | 499，含查询 | 499，含查询 |
| 筛选去重后 | 464，含查询 | 467，含查询 |
| 下游验证 | Boltz 解析并写 MSA NPZ，未重新完整预测 | 带该 A3M 的完整 Boltz 预测成功 |

因此，**同序列、同库、同候选数量并不足以说明搜索结果相同**；缓存身份至少需要包含搜索后端、工具身份、灵敏度、阈值、导出与筛选规则。464 与 467 的差异不是精度高低结论。R002 采用较早的 CPU 条件，没有显式 0.3/0.8 筛选及精确一致性计算，501 条 A3M 不能与后两者当作同一请求的可互换缓存。

这里的“CPU 分支”只指 MMseqs2，RFdiffusion 与 Boltz 仍用 GPU。切换搜索后端属于新的计算条件；精确查询未变可以省去重新设计，但不能自动将旧搜索结果归入相同条件。

## 2. 哪些产物可以复用

复用要区分“把旧产物作为新任务输入”和“相同请求直接返回旧结果”。例如同一骨架可生成多条序列，但不同温度的新序列不能直接复用旧序列并声称重新采样。

| 产物 | 可以怎样复用 | 必须核对的条件 / 何时失效 |
| --- | --- | --- |
| 模型权重、Conda 环境 | 多次任务共享部署，省去重复下载安装 | 平台、依赖、源码和权重哈希；环境存在不代表兼容 |
| RFdiffusion IGSO3 数值表 | 同参数下加载已计算的旋转噪声查找数据 | 扩散/调度参数及实现版本；不能把表当作设计结果 |
| 骨架 PDB | 同一骨架上改变 MPNN 温度、种子或约束，多次设计序列 | 坐标、链、残基编号及约束映射；骨架改变后需重新设计 |
| `.trb` | 解释骨架来源、恢复实际配置及残基映射 | 必须匹配同一骨架与源码；不是任意扩散步骤的完整续算 checkpoint |
| 扩散轨迹 | 可视化过程、比较中间几何 | 主要是分析材料；当前没有验证轨迹直接恢复完整模型状态的接口 |
| MPNN FASTA | 同一序列进行不同预测/分析，省去重新设计 | 精确序列与链；返回旧样本不能替代新随机采样 |
| MPNN 概率/评分 NPZ | 位置偏好、序列质量分析 | 依赖骨架、模型、顺序、约束和序列；自回归概率不能按位置独立采样并声称等价于原模型 |
| Swiss-Prot FASTA 和 MMseqs2 库 | 多查询共享一份库，省去下载、解压与 createdb | 固定数据库快照与建库工具版本；改变库会改变搜索含义 |
| GPU padded 目标库 | 同一目标库的多个 GPU 查询共享，省去重复 `makepaddedseqdb` | 记录源 FASTA、普通库、GPU 工具版本和库文件哈希；CPU 普通库与 padded 库分别管理，不能仅按库名前缀互换 |
| MSA 搜索结果、A3M | 相同查询与搜索条件时直接复用；同序列的 Boltz 多次预测共享 A3M | 完整序列/链、库快照、工具、参数、过滤及去重规则；设计序列一改，旧 A3M 不能直接沿用 |
| 无命中结果 | 相同查询和条件下复用“本次无命中”记录 | 是有范围的负面证据；更换数据库、阈值或工具后须重新搜索 |
| Boltz `processed/` | 同输入及兼容版本下省去重复解析与 MSA 预处理 | 需核对序列、MSA 文件哈希、链、模板、约束、配体及预处理参数；同名目录不是身份验证 |
| Boltz 最终结构、置信度 | 对同一预测请求直接展示、比较、可视化 | 模型、输入、采样/循环参数和种子均匹配；新采样请求不能直接返回旧结构 |
| PyMOL 会话及图片 | 演示、检查结构叠合 | 结构来源和残基对应关系；图片不能代替原始 PDB 与数值 |

最低建议：保留输入及哈希、配置、版本/权重哈希、日志、最终 PDB/FASTA/A3M、置信度、`.trb`、来源与状态。轨迹和搜索临时库可按预算讨论保留，但本次不删除已有文件。

### 2.1 根据本次产物提出的身份字段与完成条件

以下是 **Codex 讨论建议，尚未作为团队策略实现**。它们来自本次实际出现的文件与错误，不要求现在建设通用缓存系统。

| 希望复用的对象 | 建议共同核对的最小身份 | 本次可检查的完成条件 |
| --- | --- | --- |
| 骨架作为 MPNN 输入 | PDB 内容哈希、链/编号/残基映射、设计条件 | 可读坐标、残基数符合输入、与 `.trb` 对应；不能只看扩展名 |
| 设计序列作为搜索/预测输入 | 精确序列与链、来源骨架、MPNN 权重/配置/种子 | 选中采样记录，排除 GLY 占位；搜索 FASTA 与 Boltz YAML 一致 |
| CPU/GPU 目标库 | 源 FASTA SHA-256、工具版本/二进制哈希、建库命令与后端、配套库文件哈希 | 普通库/头库/索引完整；GPU 使用对应 padded 库；构建失败不登记完成 |
| A3M 或无命中结论 | 精确查询、源库身份、搜索后端/参数、转换及去重规则 | 首行等于查询、对齐列正确、筛选/去重计数可追溯；无命中保存查询与 `empty` 原因 |
| Boltz 预处理 | YAML 全内容、A3M 哈希或 `empty`、链/模板/约束/配体、Boltz 及解析版本 | processed 与本次输入一致，数据可读；目录/记录 ID 相同不等于内容相同 |
| 最终预测 | 上述输入身份、模型/权重、循环/采样设置、种子、相关环境 | 结构存在且序列/数量相符、置信度有限、NPZ 完整、状态 completed；新随机采样不冒充旧结果 |

哈希用于确认字节身份，不自动证明生物学有效或跨硬件逐位可复现。已有输出的回传校验也只证明保存完整，不证明这个输出适用于下一次请求。

### 2.2 失败、中间文件与保留成本

本次保留了以下对协作有实际意义的过程材料：

- R001 DGL/CUDA 启动失败和修复、Boltz PyTorch 兼容修复：解释环境为何分为两套，恢复时不能只复制依赖名称。
- R003 Hydra 自动生成目录触发预检失败、辅助 `.3/.8` 参数错误：解释源码检查与实际运行状态，失败目录不能当作可复用结果。
- R004 缺 `/usr/bin/time`、交互重复覆盖日志、验收输出定位错误及新目录成功：目录存在、子命令退出 0、通过完整验收分别判断；两份早期日志原件被覆盖的事实不得隐去。
- 搜索 `query*`、`hits*`、`alignment*`、`pref_0`、`blastp.sh` 和 `latest` 链接：解释候选与内部数据流，可用于追溯，但本次没有验证任意临时状态都能直接续算。
- 普通库/padded 库、失败分支、成功分支、日志和脚本分别清点；R004 共 201 个普通文件、5 个链接，普通文件总计 638,444,528 字节，完整压缩包 270,256,012 字节。普通库前缀占 317,583,909 字节，GPU padded 前缀占 319,799,125 字节；源压缩 FASTA 93,801,562 字节，不能用它代替建库后占用。这些只是本次快照的实测空间。

这些是已保留材料，不是已确认的长期存储策略；本次没有删除它们。按对象比较重建、读取和传输成本后再决定保留范围。完整归档尚无团队统一下载链接，Git 选集不能替代全部临时数据；两份收尾补充包仍仅在平台持久卷，具体档名与恢复限制已直接写在第一份文档第 7 节。

以下区分源码核实与本次运行验证，不将缓存存在自动解释为跨请求正确复用。

| 工具 | 已核实行为 | 限制 |
| --- | --- | --- |

## 4. 可以讨论的加速方法

| 方法 | 预期减少的开销 | 证据状态与取舍 |
| --- | --- | --- |
| 保留权重、数值表、序列库 | 重复下载、安装、数值表计算和建库 | 机制已核实；具体加速比未测 |
| 同一骨架批量采样 MPNN | 重复模型加载，部分重复计算 | 官方 CLI 提供样本数与 batch；封装当前只验证一条，扩大后须核对数量和显存 |
| 相同序列共享已验证 A3M | 重复搜索和比对 | 需要建立完整的查询与库身份，不能仅凭文件名 |
| 固定目标库切换 GPU 搜索 | 搜索计算时间 | R004 已跑通，CPU/GPU 结果有差异；这是计算后端变化，需独立对照，不能记为缓存收益 |
| 已验证科学产物直接返回 | 完整的重复科学计算 | 是工作台可研究的策略；当前封装未实现全局结果缓存 |
| 兼容的 Boltz CUDA kernels | 部分推理计算时间 | 本轮为兼容关闭；启用前需匹配 GPU/驱动/依赖并进行同条件检查 |
| 减少 RFdiffusion/Boltz 步数、recycles 或样本数 | 推理时间、部分内存 | 会改变计算条件，可能影响质量；不是无损缓存，需对照评价 |
| 减少 MSA 深度、缩小库 | 搜索、存储、MSA 特征计算 | Swiss-Prot 已用于演示，但可能降低召回；不能从无命中推广到所有数据库 |
| 长驻模型进程、合并查询 | 重复初始化或搜索调度 | 工程候选，当前未实现、未测；不在学习阶段先建设服务框架 |

### 4.1 现有耗时能用于什么讨论

R003 的一次完整设计总时长约 **112.45 秒**，RFdiffusion **38.255**、MPNN **3.472**、CPU search **11.035**、Boltz **46.721 秒**；还有预检、数据转换等开销。R004 已有序列出发的两种查询加下游共约 **73.50 秒**，GPU search 分别 **0.510/0.470 秒**，Boltz 分别 **36.303/34.501 秒**，建库 `createdb` **1.652 秒**、padded 转换 **5.345 秒**另计。

这些数值只用于识别可能值得讨论的成本来源。R003/R004 工作量、搜索条件、缓存和运行阶段不同；既没有冷/热对照，也没有重复测量、I/O/传输测量或显存峰值，因此不计算“GPU 快多少倍”或“复用省多少秒”。R004 未重跑上游是明确事实，但不是自动复用策略收益实验。缓存身份是否正确、结果是否完整和速度变化应分别评价。

## 5. 与曲鸿烨需要共同确认的内容

1. 原型先复用哪种产物：Codex 建议从固定数据库、搜索后端和精确序列的 A3M 开始，规则较清楚；骨架作为下游输入复用也容易展示。
2. 采用哪些身份字段与有效性条件；特别是同名不同内容、数据库更新、链映射变化和无命中结果。
3. 如何度量首次生成、重复计算、读取、传输的耗时与空间；需要真实测量才可报告收益。
4. 哪些中间产物用于解释与追溯，哪些值得缓存；运行失败或写入不完整的结果不能作为可复用完成项。

以上是待讨论建议，不是已确认研究控制点。建议首次对照至少记录：输入/环境/参数身份、冷启动与已有缓存两种状态、端到端及分阶段耗时、产物读取/传输时间、缓存大小、结果是否完整且对应当前请求。相同结果直接返回与改变参数后重新计算分别统计；不要将减少步数、缩小数据库造成的变化归因为缓存收益。
