01 · 问题背景

为什么“有旧结果”不等于“应该复用”？

复用也有成本。找到候选只证明它可能存在，真正决定值不值得的是：把它取回来、校验并恢复为当前步骤可消费的输入，是否明显快于重新计算。

比较的是预计墙钟时间
1

固定开销

建立连接、定位归档、发起读取等，每次复用都绕不开。它适合用 transfer_fixed_seconds 表示。

2

搬运开销

产物越大、链路越慢，搬运越久。基础模型用“大小 ÷ 带宽”估算。

3

把旧结果恢复成当前任务可消费的输入也要时间。对应 materialization_seconds。

03 · 函数与配置开关

默认不改变旧行为，显式配置后才启用成本决策

成本决策函数只接管 allow_reuse：输入是合格候选及其成本元数据，输出是复用或重算、选中候选、原因代码和可复核参数。

默认 enabled=false

比较：rerun_estimate vs reuse_estimate

1

默认关闭

未设置 AI4S_COST_POLICY_FILE 时不安装成本决策函数，原有 R01／R02／R03／R04 行为保持不变。

2

显式启用

复制示例配置并设 enabled=true；网页服务与 AiiDA daemon 指向同一个绝对路径，然后同时重启。

3

失败不静默降级

文件缺失、JSON 非法、字段未知或数值无效时显式报错；daemon 看不到所需策略时请求失败，不会偷偷换回另一套规则。

配置切换方式：将现有示例复制为部署文件；服务进程和 daemon 都设置 AI4S_COST_POLICY_FILE=<同一策略文件的绝对路径>，修改后重启两边；随后检查决策记录是否出现 R05、cost_source、rerun_source 和 reuse_source。
04 · 四条路径

用户策略决定大方向，成本决策只处理其中一个岔路

绿色复用 · 琥珀重算 · 蓝色新采样 · 红色失败
↺

1. 复用

  • 入口：用户选择 allow_reuse
  • 前提：候选合格，且预计节省达到阈值
  • 动作：只搬运、校验并复用选中候选
  • 种子：保持原种子
记录：成本策略启用时为 R05；默认关闭时沿用原规则。
↻

2. 成本判定后重算

  • 入口：用户选择 allow_reuse
  • 条件：复用不划算，或全部成本缺失而回退
  • 动作：不搬运远程候选，原参数、原种子重算
  • 结果：仍是一次真实计算
记录：成本比较做出“重算”决定时为 R05；纯缺少成本而回退时保留原规则并标 cost_source=missing。
＋

3. 新采样

  • 入口：用户选择 new_sample
  • 动作：更换有效种子并真实计算
  • 目的：获得新样本，不是查找旧结果
  • 成本：成本策略完全不参与
记录：R04。服务端生成并持久化有效种子，后续保持一致。
!

4. 失败拦截

  • 覆盖：模型失败、运行中断、检查不通过
  • 还包括：产物缺失、人工否决、模型身份不明
  • 动作：候选标记 qualified=false
  • 结果：成本再低也不能复用，改走安全重算
记录：失败原因、重试和最终决定都进入决策记录。
05 · 安全门

任何一项不通过，都先失去“被比较”的资格

成本估计只对合格候选有意义。以下情况统一视为横切安全条件，不允许用“节省很大”绕过。

qualified=false
模型运行失败没有成功产物
运行中断结果不完整
结果检查不通过科学有效性未成立
产物缺失无法恢复为输入
人工否决人或规则明确拒绝
模型身份不明哈希命中也不够
全部必须先满足：候选合格，才进入成本比较

搬运失败也要立即降级

如果成本预选选中了远程候选，但归档搬运或校验失败，该候选会被标记为不合格并记录失败原因，然后系统重新在剩余候选里决策。搬运失败结果绝不会被当作可用结果复用。

剩余远程候选会被封口

服务端预选后，所有仍未在本地物化的远程候选都会变为不可复用。这样即使 daemon 稍后读到了不同版本策略，也不能选中一个根本没有搬过来的结果；最坏情况是安全重算。

06 · 两阶段时序

为什么服务端先选一次，daemon 还要再选一次？

远程候选在服务端只有元数据。为了避免把全部候选都搬回来，服务端必须先用同一套成本口径预选；daemon 再按同一策略生成最终、可审计的 R05 决策记录。

先决策，后搬运；最终仍由 daemon 记录
01
请求进入服务 读取用户策略；只有 allow_reuse 才加载成本策略。
02
收集候选元数据 先拿到 UUID、指纹、大小、耗时、资格和来源，不立即搬运全部归档。
03
统一成本口径 跨成员历史耗时按 estimated 处理；旧记录来源未知也显式保留。
04
资格与成本比较 排除不合格候选，只比较有完整成本的数据，选预计节省最大者。
05
只物化选中项 判定重算就不搬远程结果；判定复用才搬运选中候选并校验。
06
搬运失败再决策 失败候选标为不合格，重新选择；全部失败则安全重算。
07
daemon 同策略复核 必须看到同一份有效策略；声明需要但加载不到时显式失败，不静默换规则。
08
写最终 R05 记录 记录动作、候选 UUID、种子、来源、参数和可读理由。

服务端预选

解决“不要把不需要的远程结果都搬过来”的传输浪费问题。

daemon 最终决策

解决“最终执行到底用了谁、为什么”的可审计记录问题。

同一份策略文件

解决两处口径不一致的问题；如果 daemon 看不到策略，宁可显式失败，也不悄悄采用另一套规则。

07 · 公式

四行公式，把“值不值得”变成可复核计算

每一项都能在决策记录里找到对应字段。

预计节省 = 重算时间 − 复用时间
重算侧
重算时间 = elapsed_s

elapsed_s 是候选来源记录中的非零墙钟时间。跨成员时它只作为当前环境重算时间的估计值，不直接冒充当前机器实测。

复用侧
复用时间 = transfer_fixed_seconds + size_bytes / transfer_bytes_per_second + materialization_seconds

如果候选直接提供了实测或估算的 reuse_elapsed_s，就使用该值，不再套用搬运估算公式。

选择复用当且仅当： savings_seconds > 0 且 savings_seconds ≥ min_savings_seconds。 多个合格候选都可比较时，选择 savings_seconds 最大的一个；完全相同时保留原候选顺序中的第一个。
为什么还要“最小节省阈值”？预计节省 0.1 秒虽然数学上为正，但估算误差、搬运风险和调度抖动都可能吞掉收益。阈值把“名义上省一点”与“工程上确实值得复用”分开。

09 · 成本来源

“实测、估计、缺失”必须分开写，不能混成一个数

同一个 49.9 秒，在本机实测和跨成员历史记录里的可信含义不同。R008 的 49.9 秒来源耗时是实测，0.733 秒复用耗时则是策略估算。

来源透明比数字漂亮更重要
measured

实测

  • 本机非零进程墙钟时间
  • 候选提供实测的 reuse_elapsed_s 且来源为 measured
  • 重算和复用两侧都实测时，cost_source=measured
estimated

估计

  • 跨成员／跨 profile 的历史耗时
  • 复用时间由固定开销、大小和带宽公式估算
  • 记录 cost_source=estimated，并分别写出重算与复用来源
missing

缺失

  • 缓存命中、耗时未知或不是正数
  • 大小无效、来源字段非法
  • 全部候选都缺成本时退回原简单规则，并标 cost_source=missing

部分候选缺成本怎么办？

只跳过数据不完整的候选，继续比较其余合格候选，并在原因里记录跳过的数量。不能让一个坏字段把所有候选都拖回默认规则。

旧记录没有来源怎么办？

本地旧记录按兼容规则处理；跨成员旧记录没有来源时按 estimated 处理，并保留 elapsed_origin_source=unknown，避免把来源机器实测误当成请求方实测。

Lotaru 给我们的启发：历史运行时间依赖机器、环境和工具版本；预测值必须和实测值分开，数据不足时不能假装预测可靠。本实现目前只采用这些原则，没有训练 Lotaru 式预测模型，也没有把论文误差数字当作本项目结果。
10 · 决策记录

决策记录：每一次选择都能说清楚“用了谁、为什么”

一条可解释的 R05 记录至少能回答：用了什么策略、选了谁、为什么、成本来源是什么、参数是多少。

reason_text 必须可读 
final_decision.action = "reuse"
final_decision.selected_candidate_uuid = "aae215ce-3796-4e9c-bbd6-6455cf104c08"
final_decision.effective_seed = 41
reason.reason_code = "R05"
reason.reason_text =
  成本策略选择 aae215ce-... 复用：
  重算预计 49.900s，复用预计 0.733s，预计节省 49.167s（阈值 1.000s）；
  policy_fixed=0.500s；policy_bandwidth=1048576.000B/s；
  policy_materialization=0.200s；
  cost_source=estimated；rerun_source=measured；reuse_source=estimated
reuse_policy

用户选的是允许复用、强制重算还是新采样。成本策略只能作用于 allow_reuse。

action

最终动作是 reuse、rerun 或 new_sample。看到复用决定时，还要核对候选 UUID。

selected_candidate_uuid

真正被复用的是哪一个结果。重算时应为 null，避免记录和实际执行对象脱节。

reason_code

R05 表示自定义或成本决策器给出的决定；强制重算、新采样仍按 R03、R04 记录。

cost_source

说明这次比较整体属于实测、估计还是缺失回退。看到 estimated 就不应宣称是“实测性能结论”。

rerun_source / reuse_source

分别说明重算侧和复用侧的时间来源，便于检查跨成员历史记录是否只作为估计值。

现场演示的证据点：修改参数后，选择与理由文本同步变化，说明成本参数真正参与了决策，而不是展示一条写死的文案。
