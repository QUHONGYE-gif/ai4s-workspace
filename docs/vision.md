# 面向 AI4S 工作流的语义感知数据管理与计算—存储协同工作台

## 1. 项目目标

AI4S 实验通常由数据预处理、模型计算、结果分析等多个步骤组成，会产生大量可复用的中间结果。工作台统一记录这些结果的来源、依赖和生成成本，帮助研究者管理实验，并减少重复计算与数据搬运。

同时，在多人共用服务器中，ai4s中存在大量的可复用的中间结果，为避免个人重复生成，工作台会自动调度分析是否可以复用，并提示，减少重复计算

项目首先以**蛋白质生成工作流**完成系统开发和效果验证，再逐步接入其他 AI4S 场景。

## 2. 核心研究问题

> 系统能否依据科学数据的语义、依赖关系和计算成本，比普通文件缓存更准确地决定中间结果何时复用、何时重算、是否保存？

初期聚焦三个问题：

1. **数据如何识别？** 用输入、算法、参数、模型及数据库版本等信息定义中间结果的身份和依赖关系。
2. **数据如何复用？** 判断已有结果是否仍然有效，并比较加载与重算的成本。
3. **数据如何存放？** 结合复用价值、数据大小和存储空间，决定保留及放置策略。

计算任务调度可以在上述能力稳定后，作为计算—存储协同优化的扩展研究。

## 3. 工作台主要功能

- **工作流接入：** 通过统一接口描述任务步骤及其输入、输出，先接入蛋白质生成流程。
- **科学数据目录：** 记录中间结果的身份、版本、依赖、位置和生成成本。
- **复用与存储策略：** 自动判断结果的有效性，并选择复用、重算或保存。
- 多人共同产物判断：判断要生成的内容是否有已生成内容，选择复用或者重新生成
- **实验管理与可视化：** 在网页端查看工作流、数据依赖、运行记录和结果；蛋白质结构可接入专门的可视化工具展示。

## 4. 初步试验：蛋白质生成

选择从rfdiffusion->proteinmpnn->alphafold/boltz 为基础pipeline，序列处理、embedding、MSA、结构预测等步骤作为首批任务，重点验证：

- 参数或模型改变后，哪些中间结果仍可复用；
- 复用与重算决策能否缩短实验运行时间；
- 不同保存策略对存储占用和重复计算的影响。

将无缓存、LRU 等作为对照，以运行时间、重复计算量、数据加载时间和存储占用为主要指标。

## 5. 实施阶段

1. **原型阶段：** 完成工作流接入、数据目录、依赖记录和网页端基本展示。
2. **策略阶段：** 实现有效性判断与基于成本的复用、重算和保存策略，并在蛋白质生成场景中评测。
3. **扩展阶段：** 接入第二类 AI4S 工作流，检验通用接口的适用性；再视实验结果研究分层存储和任务调度。

## 6. 项目特色与边界

项目的重点是为科学中间数据建立**可判断、可复用、可追溯**的管理机制，并将其集成到易用的 AI4S 工作台中。初期蛋白质实验可以证明该场景下的效果；只有接入第二类工作流后，才能进一步验证工作台的跨领域通用性。
