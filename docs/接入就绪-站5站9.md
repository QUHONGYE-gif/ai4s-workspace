## 1 给站 ③④（曲鸿烨）：CalcJob 节点要满足什么

### 1.1 我这边的读取假设只有四条

1. **指纹在 `extras._aiida_hash`**：AiiDA 自己在缓存判定时写的那个键，正常执行完的过程一定有。
   站 5 只读不算——两边各算一次指纹，Code 的 UUID 参与哈希，必然对不上。
2. **产物通过 `create` 链接挂在过程节点下**：`FolderData` / `SinglefileData` / `Dict` 都行。
3. **仓库型产物（FolderData 等）必须有文件**：一个文件都没有会判 `missing_file`；
   `RemoteData`（没 retrieve）单独判 `missing_file: 产物仍是 RemoteData`。
4. **序列结果放在 FASTA 里，header 带 `score=`**：只数 `>` 开头行计算条数，只解析 `score=` 与
   `global_score=`；`global_score` 不会被误当成 `score`（已用负向断言排除）。

不假设的东西：不假设节点类型、不假设文件路径、不假设 Code、不假设 Computer。
产物在 `retrieved/seqs/design.fa` 还是 `seqs/design.fa` 都能读，因为目录是递归列出来的。

### 1.2 一条命令看自己的节点行不行

```bash
export PYTHONPATH=$PWD/src
python -m ai4s_query.cli preflight --profiles ai4s --limit 30
```

输出逐条给结论，三种标记：

```
体检范围 ai4s　检查 30 个过程　ready 27 / partial 2 / blocked 1

✔ pk=312 mpnn run=3 out=FolderData files=6 seqs=8
    · 可直接作为候选
△ pk=305 mpnn run=2 out=FolderData files=6 seqs=0
    · 找不到 FASTA（.fa/.fasta/.faa）：条数与分数判定会跳过；
      若这次确实是结构设计任务，请把序列写进 *.fa 并保留 header 的 score=
✘ pk=298 mpnn run=1 out=RemoteData files=0 seqs=0
    · 产物是 RemoteData：retrieve 没做完。CalcJob 需要 retrieve_list 或 parser 里完成取回后，
      由 FolderData 承接
```

`ready` 就是「我这边能把它读成候选」；`partial` 能读但少东西（如没有 FASTA，条数与门限两级判定失效）；
`blocked` 完全读不出来，附原因。退出码：全部 ready 为 0，存在 blocked 为 2，方便挂 CI。

### 1.3 我这边的判定顺序（知道它会怎么判你的节点）

| 级 | 检查 | 不过时 |
|---|---|---|
| L1 | `finished` 且 `exit_status = 0` | `not_finished` |
| L2 | 有输出节点；仓库型产物有文件且非空 | `missing_file` / `format_error` |
| L3 | 序列条数 ≥ 请求的 `num_sequences` | `insufficient` |
| L4 | 最优 `score` ≤ 请求门限 | `below_threshold` |
| L5 | 人工复核 | `manual_reject` |

CalcJob 的 `exit_status` 与 calcfunction 的「无 exit_code」都走 L1：判据是 `exit_code in (None, 0)`，
所以两种节点类型不需要分支。

## 2 给站 ⑥⑧（吴昱慧）：怎么写、写在哪、怎么自查

### 2.1 先拿骨架

```bash
python -m ai4s_query.cli decision-write - --template > decision.json
```

生成的 JSON 与约定⑤ 的 7 字段一一对应，`candidate_compare_list` 里每一项的
`uuid / fingerprint / member / qualified / reason` 可以直接从站 5 的候选结果里拷，不需要重组。

### 2.2 一条命令写入

```bash
python -m ai4s_query.cli decision-write decision.json --process <过程 UUID>
# 默认两处都写：节点 extras + ~/runs/decisions/<request_id>.json
# 只写文件：--targets file   只写节点：--targets attributes
# 载体由团队定下来之后，用环境变量 AI4S_DECISION_STORE 一处切换，调用方不用改
```

写入前会按 ⑤ 校验，**校验不过默认拒绝写**（避免脏记录进库），确需强写加 `--force`。
校验项包括：7 字段齐全、`reuse_policy` 与 `final_decision.action` 自洽、理由码在 R01–R05 内、
`R01` 只能配 `reuse`、`new_sample` 必须给 `effective_seed`、`reuse` 必须给 `selected_candidate_uuid`、
不合格候选必须带 `reason`。

### 2.3 关于「存哪」：实测结论是 extras，不是 attributes

我原来的建议是把记录写进过程节点的 `attributes.ai4s_decision`，**实测不成立**：

```
aiida.common.exceptions.ModificationNotAllowed: attributes of a sealed node are immutable
```

过程一终止就 seal，sealed 节点的 attributes 与仓库都不可改。能写的是 **`extras`**——
extras 不受 seal 限制，且和 attributes 一样随节点走、随备份走。
所以现在是：优先写 `extras.ai4s_decision`，不行再退 `attributes`（只对未 seal 的过程有效）。
读取端两处都读，站 ⑩ 无感。

如果团队最终仍要另立存储（如飞书多维表格），只需在 `decision.py` 的 `_targets()` 加一个分支，
接口与页面都不动。

### 2.4 写完自己验一遍

```bash
python -m ai4s_query.cli decision <request_id>
# 或在页面上：curl 'localhost:8848/api/decision?request_id=<request_id>'
```

读到即算闭环：来源会显示 `extras` 或 `file:…`，校验显示「通过」。

## 3 给站 ⑩（邹佳轩）：新增的字段与两个注意点

1. **候选多了三个扩展字段**（④ 的 9 个字段语义不变）：
   `out_kinds`（产物节点类型）、`best_global_score`（global_score 最优值）、
   `note` 里会出现「仅值（无文件产物）」或「RemoteData 未 retrieve」。页面可只用 `note` 做提示。
2. **产物在输出节点上，不在过程节点上**：`/api/node/<过程UUID>` 的 `repository` 里只有
   calcfunction 的源码快照；要列产物，用 `/api/node/<产物UUID>` 或 `/api/trace/<过程UUID>`。
3. **决策记录缺失不是错误**：`/api/decision` 返回 `count = 0` 且带 `missing` 文案，按空态渲染。
4. **不要在前端判合格性**：判定在内核侧完成，前端只渲染 `qualified` 与 `reason`。

## 5 本轮实测记录（2026-11-11）

### 5.1 CalcJob 形状的产物被读成候选

用 `examples/run_calcjob_shape_demo.py` 造一个与真实 ProteinMPNN 同构的过程
（产物 `FolderData`：`seqs/design.fa` + `scores/design.npz` + `run.json`）：

```

```

要点：产物是目录结构、文件在子目录里、分数在 FASTA header 里——这些都与 calcfunction 的
`Dict` 完全不同，但站 5 的代码一行没改就完成了读取和判定。

### 5.2 边界判定

```
值型产物（Dict 无文件）      → 合格（④ 允许 size_bytes=0 + note「仅值」）
仓库型产物但没文件           → missing_file: 仓库型产物内没有任何文件
RemoteData 未 retrieve      → missing_file: 产物仍是 RemoteData，retrieve 未完成
有 FASTA 但条数不够          → insufficient: 仅 2 条序列 < 要求 8 条
```

后三条是这次补的：原来「没有文件」一律按「仅值」豁免，会让没 retrieve 的 CalcJob 被判合格。
