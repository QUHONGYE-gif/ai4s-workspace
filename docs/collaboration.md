# 团队协作约定

状态：用户于 2026-10-18 确认。原话见 [用户要求](vision.md)，实际配置进度见 [当前状态](status.md)。本文件统一维护个人开发、汇总和合并规则。

## 个人开发

- 每人使用自己的 Coder 账户和工作区，维护独立代码副本，不在同一宿主机 checkout 中轮流切换个人分支。
- GitHub 个人开发分支命名为 `dev-姓名三字首字母`，使用小写拼音首字母，例如首字母为 `qhy` 时使用 `dev-qhy`。遇到首字母重名时先协调唯一名称，不复用其他成员的分支。
- 各自在个人分支提交和推送；需要同步团队进展时，将 `origin/main` 合入自己的开发分支并处理冲突。个人提交、测试通过都不代表获准合入 `main`。
- 个人凭据和环境配置留在各自工作区；共享科学产物按项目数据约定存放，不通过共用代码目录实现协作。
- 个人修改可通过 [开发预览](development_preview.md) 在自己的容器中验证；是否提交、创建 PR 或合并，不影响个人页面的运行。

## 汇总、会议与合并

1. 开发者通过面向 `main` 的 PR 汇总改动，说明目的、修改范围、验证结果和待讨论问题。尚未准备好或会议待定时可保持 Draft。
2. 团队汇总各 PR 的依赖、冲突和影响，会议讨论后明确通过、修改后再议或暂缓。
3. 在 PR 中记录会议日期、结论以及通过的提交版本或范围；会议记录可用团队可访问的链接，或在 PR 中填写简短结论，不要求新建独立会议管理系统。
4. 只有完成汇总并经会议通过的改动才能合并到 `main`；未经通过不得直接推送、合并或让自动化代为合入。通过后发生超出会议批准范围的实质修改，需要再次确认。

PR 是落实汇总与留痕的方式；会议批准由团队确认，不能用 CI 通过或 Agent 的判断替代。使用 [PR 模板](../.github/pull_request_template.md) 保留必要信息，不预设固定的参会人数、审查人数或指定合并人。

## 配置落实与自动化

个人工作区使用新增的 `server-personal` 模板，在每个工作区的独立持久卷中克隆代码；开户、分支初始化及种子更新见 [成员操作说明](members.md)。原型模板的 `project_path` 仍挂载同一宿主机仓库副本，不能将该旧模板当作已隔离的个人环境。已接入成员及验证范围见 [当前状态](status.md)，资源上限见 [环境说明](environment.md)。

后续 CI 可以检查个人分支和 PR；共享部署以会议通过后进入 `main` 的版本为来源，具体触发方式见 [CI/CD 计划](cicd.md)。个人分支不得自动替换共享部署。

GitHub 分支保护的实际启用状态在状态文件维护；会议通过这一条件仍需团队在 PR 中记录和核对。自动化和 Agent 均应遵守 [项目规则](../AGENTS.md)。
