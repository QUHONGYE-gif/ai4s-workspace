# 科学计算任务注册中心与声明交付

本页面完成约定①的声明编辑、真实 Agent 提案、用户确认和 JSON 导出。声明规则以 [约定①](task_declaration_contract.md) 为准，完整声明文件为 [proteinmpnn/1.json](../configs/task_declarations/proteinmpnn/1.json)。当前支持真实任务接口的 `single` 和 `mpnn_filter` 定义；导出不等于引擎已登记，也不等于实验已提交。

## 使用入口

沿用 [Agent 工作流接入的启动方式](agent_demo_run.md#安装和启动)，从工作台侧栏打开 **任务注册中心**（`workbench.html#/tasks`）。工作流列表中的 **工作流编辑器**（`#/workflows/editor`）直接打开画布，不再经过多层模式切换。旧 `#/workflows/new?mode=ai` 链接仍进入注册中心。

导航按“任务注册中心 → 声明”和“工作流 → 工作流编辑器”组织，页面之间不放互相跳转的按钮。

注册中心列出仓库声明及版本、编辑草稿和后续任务类型。仓库声明只读；“创建编辑副本”不会修改仓库文件。新建草稿可选择已核验任务及依据版本，再从空白接口或完整定义起步。当前只有 ProteinMPNN 具有正式校验支持；RFdiffusion、Boltz、MMseqs2 仅列为待接入，不提供可发布声明或执行入口，也不支持仅凭未知名称生成正式声明。

统一编辑器根据所选声明显示名称、输入、参数分组、范围及跨字段约束、输出与阶段、执行映射。缺项保留逐项填写入口；AI 助手默认展开，可从侧栏图标收起和展开。声明规则与适配器核验仍按任务类型实现，本轮没有把 ProteinMPNN 的已知语义改成任意 JSON Schema 或可执行代码。

1. 在注册中心点击“新建声明草稿”，或从仓库版本“创建编辑副本”。草稿保存在现有 Agent 服务的数据目录 `declaration_drafts/`，不写入发布目录。
2. 页面展示输入、推理／筛选参数、必填性、真实默认值、范围、输出及所属阶段。展开“试填联调参数”可编辑示例；示例值与后端默认值分开。
3. 点击具体项目的“填写定义”或“编辑”，逐项填写，也可引用此项已核实定义，再点击“预览此项修改”。“请助手协助”会展开侧栏并填入针对该项的请求，由用户发送；也可粘贴／读取文本资料说明修改要求。“高级 → 批量补齐”保留一次补齐所有缺项的操作。真实 DeepSeek 调用需要先在页面配置 API；密钥仅存服务端，不包含在声明、公开响应及 Git 中。
4. 助手只生成提案。查看目标字段、旧值、新值和来源后，“确认并写入”整批保存；取消不改变已保存声明。普通问答不修改声明。缺项可保留为草稿，但不能导出；非法值和接口冲突整批拒绝，不部分保存。
5. 编辑器“校验并导出”下载 `<version>.json`。缺项、类型错误、虚构默认值、不支持的端口／执行映射都会阻止导出。已发布版本内容不可覆盖，自定义内容需使用新接口版本；这不意味着新版本已经获团队批准。
6. 把通过审核的文件交给发布负责人，纳入 `configs/task_declarations/<task_id>/<version>.json` 并部署。完整责任与加载规则见 [约定①](task_declaration_contract.md)第9节。

本轮可校验与导出的声明只接受已核实 ProteinMPNN 接口。资料可用于解释、补齐和填写合法示例；不能仅凭 Agent 改写科学参数语义或支持新模型。恢复定义只补缺项，保留已经编辑的名称、说明和示例。已有表单编辑须先确认或显式读取保存版本，再发送对话，避免两种编辑互相覆盖。

## 删除与恢复

声明草稿列表提供“删除”，工作流编辑器的“历史 / 新建”窗口提供“删除所选”。确认后记录移入各自回收站，可恢复；正式仓库声明不提供删除。操作校验修订版本，删除和恢复均增加修订，旧提案不能直接写入恢复后的记录。恢复声明后须重新校验导出。

删除不影响其他草稿、上传文件、已下载 JSON、实验与科学结果。删完最后一份工作流显示空状态，刷新不会自动创建替代示例。回收站只保留当前单用户服务的记录，不是跨成员权限或审计系统。

接口使用 `GET /api/declaration-drafts?deleted=true`、`GET /api/workflows?deleted=true` 查看回收站；对对应记录 `POST .../{id}/delete` 或 `POST .../{id}/restore`，请求沿用 `expected_revision` 和 `operation_id` 字段。删除／恢复只按修订检查，不缓存操作回执；网络重试收到冲突时须刷新确认。

## 状态与工作流实例边界

| 对象／状态 | 当前含义 |
| --- | --- |
| 仓库版本 · 网页已加载 | 经过现有加载器验证的声明文件；不代表真实引擎加载、运行时 Code 可用或网页可提交 |
| 草稿，未发布 | 编辑中的接口定义，可有缺项；与节点参数独立 |
| 已校验导出，未部署 | 当前修订已完整校验并导出；内容继续修改后恢复草稿状态，不代表审批或发布 |
| 审核与发布 | 仍按约定①的负责人审核、入库与部署流程，不提供网页自动发布 |
| 引擎加载／可执行／已提交／已完成 | 需实际引擎状态和执行证据；本轮网页不报告这些状态为成功 |

`GET agent/api/task-catalog` 汇总受支持声明、依据版本、适配器源码支持和网页执行未接通状态。草稿创建请求新增可选 `task_id`、`version`（依据版本），不提供时兼容旧 ProteinMPNN v1 请求；未知任务或未知依据版本返回422。草稿另存依据引用与最近导出修订，旧草稿缺少这些元数据时按原 ProteinMPNN v1 读取。已发布 JSON、约定①格式、科学约束和 AiiDA 接口均未迁移。

工作流编辑器仍使用三模型 `demo-1` 数据和演示参数校验，不是正式声明的节点实例编辑器。节点面板会显示其演示定义版本、当前节点标识以及“尚未绑定正式任务声明”，并显示仓库声明可用情况。“确认节点配置”只生成原有配置快照，不发布声明。参数、输入和后续结果必须属于具体节点；修改其中一个节点不会修改仓库声明，也不会修改另一节点。

后续真实联动需完成：在节点保存不可变 `(task_id, version)` 声明引用及内容摘要，依据该版本生成输入／参数／输出表单；节点另存实例输入引用和具体参数；服务端按声明及对应适配器验证并拒绝未知字段。旧 Demo 的 `num_seq_per_target`／`sampling_temp`、链策略和端口与真实 `num_sequences`／`sampling_temperature`／`pdb_file` 不等价，不自动迁移为可执行节点。先明确版本迁移及输入语义，再接约定②和 AiiDA；同一声明可被多个独立节点引用。第二种真实任务接入时应增加自己的校验器与适配器，以其真实接口验证当前展示层的可扩展性。

## 实现与引擎交接

| 内容 | 入口 | 边界 |
| --- | --- | --- |
| 版本化声明文件 | `configs/task_declarations/proteinmpnn/1.json` | 普通 JSON，无密钥、服务器路径或任意命令 |
| 共用校验／文件加载器 | `src/ai4s_declarations/registry.py` | 标准库，不依赖 AiiDA；验证全部文件后才可用，非法 JSON、重复字段、路径／版本不一致会阻止加载 |
| 草稿与确认 API | `src/ai4s_demo/declarations.py` | 单用户、单进程 JSON 存储；修订冲突与重复确认保护；不提供发布注册接口 |
| 真实模型助手 | `src/ai4s_demo/declaration_agent.py` | PydanticAI + 现有 DeepSeek 网关，独立审核修改意图，后端校验后只生成提案 |
| 登记页面 | `src/ai4s_demo/web/declaration.js` | 在现有工作台中挂载；前后端均沿用路径前缀 |

引擎组可以复用加载器：

```python
from ai4s_declarations import DeclarationRegistry

registry = DeclarationRegistry("configs/task_declarations")
declaration = registry.get("proteinmpnn", "1")
# 未登记的引用抛出 KeyError("invalid_declaration")，由引擎按约定②映射响应。
```

网页服务和[真实引擎服务](engine_service.md)现在共用同一声明加载器。引擎已解析正式声明引用，并完成输入检查、模型身份、builder、状态与④⑤查询；运行证据见 [R007](../experiments/R007-member-reuse/record.md)。网页草稿仍须经审核入库并部署后才成为可执行版本，导出不会自动发布。草稿 API 与约定②提交接口操作不同对象。

接口清单：

- `GET /api/task-declarations`、`GET /api/task-declarations/{task_id}/{version}`：已加载定义。
- `GET/POST /api/declaration-drafts`、`GET /api/declaration-drafts/{id}`：编辑草稿。
- `POST .../{id}/preview`、`POST .../{id}/messages`：生成手动／Agent 提案，不写入声明内容。
- `POST .../{id}/confirm`、`POST .../{id}/cancel`：按提案编号明确确认／取消；确认接口只使用服务端保存的候选内容。
- `POST .../{id}/export`：完整校验后返回声明、内容 SHA-256 与交付路径，状态为 `exported_not_deployed`。

除新建外，修改、消息和导出请求都带 `expected_revision` 与 `operation_id`。生产环境仍需成员鉴权、权限及多进程存储；当前沿用个人 Coder 工作区的单用户原型，不扩大现有部署边界。

## 验证记录

自动化验证命令：

```bash
uv run pytest -q
node --test tests/*.cjs
```

本次本地回归为 **63项 Python 测试、5个 JavaScript 测试文件全部通过**。已验证既有测试及新增声明测试：完整定义与协议附录一致，拒绝非法种子／类型／整除关系／未知字段，缺项阻止导出；预览不写入、取消不写入、确认只写一次、旧修订拒绝；同版本发布不可变、恢复缺项保留用户修改、非法 Agent 批次不部分保存、旧流程数据保持独立。模型替身测试仅验证程序机制，不作为真实 LLM 证据。

另外将推理规则与 `source_reference.revision` 指定的 A 模块源码逐字核对：14组合法／非法参数用例和3个真实后端默认值一致。筛选规则保持有限阈值、正整数 top_k，不增加0～1范围或生成条数上限。此项是接口一致性检查，不是模型效果评估。
