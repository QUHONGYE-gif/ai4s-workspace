# 分阶段实施计划

状态：Codex 建议的初步安排，2026-10-18。依据 [项目设计草案](research_plan.md) 和 [用户原文](vision.md)；用户已追加授权本地 Docker + Coder 初始化及服务器 Docker 配置；其余工作台实现、模型接入和评测任务仍为计划，实际完成状态见状态文件。

本文件只维护任务顺序、产物和阶段完成条件。数据对象、复用含义与评价指标以设计草案为准；实际进展统一写入 [状态](status.md)，服务器信息引用 [环境](environment.md)。

## 开发底座

按照已选开发模式建立 Compose 配置、Coder Docker 工作区模板和初始化入口，检查服务访问、工作区连接、仓库读写及持久化。操作说明见 [本地 Docker 运行说明](local_docker.md)；实际版本和位置只在环境文档维护，不在本计划复制。

服务器配置按 [服务器运行说明](server_docker.md) 执行，保持数据盘存储、资源限制和现有任务隔离。

多人启用前按 [团队协作约定](collaboration.md) 配置个人账户、工作区及独立代码副本，验证各成员切换分支和修改文件互不影响；同时核对合计资源上限。个人分支与会议合并流程按该约定执行。

这一步完成后，继续下面的科学工作流接入准备；开发底座可用不表示工作台业务或蛋白质流程已实现。

## 准备：确定第一条可执行链路

- 查阅候选工具的官方实现，确认实际版本、输入输出、权重／数据库获取条件和运行资源；可以直接接入现有脚本，不要求重写模型。
- 选择小规模输入及一条能够运行的蛋白质链路；明确哪些产物值得先记录，以及哪些候选步骤属于可选分支。
- 核对项目专用执行目录和环境，保护服务器原有项目；依赖、模型和数据位置确定后更新环境文档。
- 形成简短接入说明，包含步骤依赖、示例输入、执行入口和限制。仅在此时按需要创建代码目录及依赖声明。

完成条件：能说明首条链路要执行什么、各步骤如何连接，以及最小输入是否具备运行条件。若后端暂不可用，可以先接入已可运行的步骤；模拟产物只用于界面或逻辑检查，明确标注，不当作蛋白质流程验证。

## 原型：打通提交、记录、查询和展示

1. 为选定步骤提供轻量接入方式，记录实际输入、输出和依赖。优先适配现有脚本调用，避免先建设通用插件框架。
2. 建立最小产物目录及运行记录，支持按生成条件查找候选、查看来源和定位文件。元数据存储与网页技术栈在实现时选择，优先使用团队已有技术。
3. 将一次小规模真实执行的产物登记到目录，再用相同请求查询，输出复用提示；保留首次生成与后续使用的关联。
4. 用不同请求者标识检查共享查询、完成状态和可读取性；先支持已有结果检索，进行中的重复请求可先提示。
5. 网页展示工作流步骤、依赖、运行状态、产物及决定理由。蛋白质结构展示可接入现有查看器，选型后再补入口。

完成条件：至少一条真实的小流程能够被记录、再次检索，并在网页查看来源和状态；共享案例能够解释候选为何可复用或不可复用。此阶段不要求自动作业调度、所有模型后端都可用，或证明性能优势。

候选文件位置：可复用逻辑放 `src/`，执行入口放 `scripts/`，实际配置放 `configs/`，关键检查放 `tests/`；前端目录按选定技术栈建立。以上均按实际需要创建，不先填充空模块。

## 策略：从有效性规则到成本和空间预算

1. 围绕设计草案中的身份与有效性案例检查判断逻辑，先覆盖实际接入的步骤，不写跨所有科学场景的规则系统。
2. 采集生成、读取、搬运耗时及大小，加入简单成本比较；记录估计值与实际值，观察策略何时适用。
3. 在独立的实验输出范围内实现空间预算及一种保留策略，并与 LRU 等对照；保护原始数据、其他用户文件和既有结果。
4. 用同一组请求完成小规模对照，再按结果决定是否扩大输入或重复运行。评测条件和指标定义直接引用设计草案，避免维护第二份协议。
5. 记录实际运行身份、日志和结果；将误复用、重复计算、无收益和策略开销一并报告。

完成条件：决定可解释，关键案例检查有结果；获得一次能够追溯条件和开销的对照记录，并说明收益、无收益或限制。完成条件不要求本策略在所有指标上领先。

只有真实运行时才建立 `experiments/R编号-主题/record.md`；文件至少记录问题、状态、实际代码／配置／环境、数据、种子（适用时）、命令、关键结果和产物位置。实验细节不堆入本计划。

## 扩展：检查接口适用范围

- 基于已完成的蛋白质原型选择第二类工作流，选择理由和新增依赖届时记录，不在本轮预定。
- 先接入少量步骤，记录沿用的接口、必须增加的字段及无法直接复用的规则，再考虑更广范围。
- 根据实际访问、传输和排队开销，决定是否研究分层存储或任务调度；两者可以分别推进。

完成条件：有第二类真实工作流的接入证据和接口差异说明；只声明已测试范围。若当前核心功能尚需修正，可以延后扩展。
