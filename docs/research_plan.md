## 范围与任务顺序

| 范围 | 当前定位 | 与后续工作的关系 |
| --- | --- | --- |
| 单个工作流中的产物记录、依赖和结果查找 | 第一条原型链路 | 为复用和界面展示提供基础 |
| 多人产物检索、有效性判断和复用提示 | 首期核心能力 | 与单人复用共用目录，额外记录产物来源和访问情况 |
| 基于成本的复用／重算，以及有限空间下的保留策略 | 原型可运行后展开 | 先观察真实成本，再调整策略 |
| 第二类工作流 | 扩展阶段 | 检查哪些接口能复用、哪些需要适配 |
| 分层放置、任务排队和计算资源调度 | 后续候选 | 视前面结果及需求决定，不作为第一版必备功能 |

这里的“自动分析”先指在步骤提交时检索目录、检查候选、比较成本并给出决定或提示。它不必先实现 GPU 作业调度。是否直接执行复用或交由用户选择，可在原型使用中调整，并保留决定理由。

## 最小数据组织（建议）

| 对象 | 必要内容 | 用途 |
| --- | --- | --- |
| 步骤描述 | 输入产物、算法／代码、相关参数、模型／权重与数据库版本；涉及随机生成时记录种子和采样意图 | 表达本步骤实际依赖，生成可比较的结果身份 |
| 产物记录 | 类型与科学含义、身份、上游依赖、位置、大小、完成状态、生成来源和共享范围 | 判断候选是否适合当前请求并且可读取 |
| 运行记录 | 使用的步骤和产物、执行环境、耗时、输出及状态 | 区分真实生成、复用和失败，并追溯来源 |
| 决策记录 | 候选产物、复用／重算理由、估计与实际成本、保留决定 | 解释策略行为，支撑后续评测 |

“语义”初期由明确字段和步骤依赖表达，例如数据类型、单位、处理方式及版本；不必先引入语言模型或语义相似度模型。内容相似、文件同名或同一路径不能单独证明结果等价。

结果身份描述生成条件；有效性还取决于产物是否完整、可访问，以及当前步骤是否接受其格式和含义。模型或参数变化只影响依赖这些信息的步骤；不因整个工作流改动就统一废弃所有中间结果。第一版可先保守地匹配明确依赖，跨版本兼容规则按实际案例补充。

对生成任务应区分“重放同一次结果”和“需要新的随机样本”。即使输入、模型和主要参数相同，新的采样请求也不应被旧结果直接替代；具体身份规则随接入步骤确定。

## 判断与共享行为（建议）

1. 接收步骤请求，整理其实际依赖和预期产物。
2. 在个人及允许共享的目录范围内查找候选，检查生成条件、完成状态和可访问性。
3. 对有效候选比较读取／搬运成本与重算成本，输出决定及理由；没有可靠成本记录时可先使用简单规则，并标记估计来源。
4. 复用时将当前运行关联到原产物及生成者；重算时登记新产物，完成后再作为可复用候选。
5. 根据空间预算、生成成本和观察到的再次使用情况决定保留或放置。先实现一种可解释策略，再按评测需要扩展。

多人情形还应区分“已经完成”与“别人正在生成”。第一版可以提示进行中的同类任务，并允许等待或另算；是否实现统一等待和重复任务合并留到有实际需求时决定。不因为目录记录存在就认定物理文件仍存在，也不因为共享路径相同就认定所有用户均可读取。

## 首个场景的接入边界

用户提出的候选链为 `RFdiffusion → ProteinMPNN → AlphaFold／Boltz`；原始需求见 [vision.md](vision.md)。规划先围绕生成、序列设计和结构预测组织步骤，各版本的实际接口及可运行组合需要查证。

序列处理、embedding、MSA 作为候选步骤或分支，依据实际工具输入输出接入，不预设每种预测后端都必须经过它们。共享复用优先挑选依赖能够明确描述、原始生成条件可追溯的产物；具体版本、输入样例和首批产物类型由 [实施计划](implementation_plan.md) 的准备阶段确定。

## 初步评价思路

先检查决定是否合理，再观察资源收益。运行成功、原型可用和策略有效分别报告；没有改善也可以完成一次有效评测。

| 关注点 | 初步观察方式 |
| --- | --- |
| 身份与有效性 | 构造相同请求、相关／无关参数变化、上游变化、产物缺失或未完成等小案例，检查复用理由 |
| 多人复用 | 使用不同请求者记录重复请求，观察是否命中可访问的共享结果，来源是否可追溯；单账户模拟须明确标注 |
| 时间与数据搬运 | 总耗时包含目录检查和策略开销；读取与传输耗时分开记录，观察复用是否实际节省时间 |
| 重复计算 | 记录已有可用等价结果却再次执行的次数和计算耗时；新采样请求不计为本应复用的重复计算 |
| 存储 | 记录保留产物大小、峰值占用、淘汰后再次计算及产物搬运情况 |

对照首先采用用户提出的无缓存、LRU 与本项目策略。LRU 与本项目策略尽量使用相同的候选匹配规则，仅改变保留选择，以便解释差异；若要单独考察语义身份判断的价值，可增加按文件路径或简单键查找的缓存对照。对照细节在真实评测前根据原型能力确定，不要求一次覆盖所有组合。

优先用同一组请求、输入、工具版本及存储预算比较；明确冷启动、已存有产物和空间受限等条件。涉及随机生成时控制对应种子和采样意图；需要重跑时使用独立输出目录。初期只要求结果可解释、主要开销可追溯，不预设性能提升幅度或统计显著性门槛。

蛋白质场景的结果限定在该工作流和测试条件内；接入第二类工作流后再讨论接口适用范围，不由一个场景直接宣称跨领域通用。
